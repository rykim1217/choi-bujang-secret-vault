# 3일차 · 연결·Windows 기록

기존 제공 코드에는 해당 로컬 조회가 없었습니다. student/pc-system.mjs(조회), pc-system-view.mjs(표시)를 추가하고 pc-server.mjs, pc-dashboard.mjs, pc-dashboard.css를 연결했습니다. 제공 서버·public/app.js·인증·판정 코드 및 기존 제출물은 변경하지 않습니다.

## 실행과 확인

기존 on-client 폴더에서 `npm run start:pc`를 실행하고 http://127.0.0.1:5190/ 에 접속합니다. 이미 서버가 실행 중이면 해당 실행 창에서 Ctrl+C 후 같은 명령으로 재실행합니다.

1. 왼쪽 연결·Windows 기록을 누릅니다.
2. 지금 조회를 한 번 누르고 네트워크·방화벽·Windows 기록·SDP 카드 네 개를 확인합니다.
3. 상세에서 어댑터별 IP·게이트웨이, 프로필별 방화벽 설정, System/Application의 경고·오류 건수와 시각을 확인합니다.
4. 읽지 못한 항목은 확인 불가와 이유가 표시되는지 확인합니다. 미조회·실패는 0건이 아닙니다.
5. 내 PC 상태로 돌아가 기존 CPU·메모리·디스크 화면이 유지되는지 확인합니다.

## 읽기 근거·범위

- PowerShell Get-NetAdapter/Get-NetIPConfiguration: 현재 어댑터 상태와 IP·게이트웨이 구성만 조회. 인터넷 도달 가능성을 시험하지 않습니다.
- Get-NetFirewallProfile -PolicyStore ActiveStore: 도메인·개인·공용 프로필의 Enabled 설정만 읽습니다. 실제 패킷 허용 여부나 전체 보호 상태 판정이 아닙니다.
- Get-WinEvent: 조회 종료 시각 기준 최근 24시간, System/Application, Level 2(오류)·3(경고). 조회 범위와 항목별 시각을 표시합니다. 경고·오류 건수는 침해나 공격 탐지 결과가 아닙니다. 해당 범위의 항목 없음 응답만 0건으로 처리하며 그 외 오류는 확인 불가입니다.
- 일반 권한만 사용합니다. 관리자 실행을 감지하면 조회를 거절하고 이유를 표시합니다. 설정 변경, 권한 상승, 방화벽 규칙 수정, 공격·침투 시험은 없습니다.
- 현재 start:pc 실행 경로에는 SDP 호스트 구성이 없으므로 SDP 미연결을 별도로 표시합니다. PC 조회 성공이나 다른 어댑터 설정을 SDP 연결 증명으로 사용하지 않습니다.
- 실제 PC 조회만 사용하고 예시 데이터로 대체하지 않습니다. 로컬 서버는 127.0.0.1에만 수신하며 IP 등 조회 내용을 외부 전송하지 않습니다.
- 조회 기록은 해당 화면에서 최근 10회만 보관하고 새로고침하면 초기화됩니다. 요청 제한 시간 25초, 중복 요청은 같은 진행 중 조회를 공유합니다.

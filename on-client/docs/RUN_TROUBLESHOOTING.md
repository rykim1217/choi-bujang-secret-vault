# 라요 · 처음 실행하는 분께

## 1. 무엇을 실행하나요?

이 안내는 Windows PC에서 라요 PC 대시보드를 실행하는 방법입니다. 현재는 설치 파일이 아니라 프로젝트 폴더로 실행합니다. 일반 사용자 권한을 사용하고 관리자 PowerShell은 열지 마세요.

| 메뉴 | 확인할 수 있는 것 |
|---|---|
| 내 PC 상태 | 실행한 PC의 실제 CPU 사용률, 메모리 사용량, 시스템 드라이브 남은 공간 |
| 연결·Windows 기록 | 네트워크 구성, 방화벽 프로필 설정, 최근 24시간 System/Application 경고·오류 건수 |
| 보호 현황·업무 앱·보안 기록 | 기존 서버 연동 기능. 현재 구성에서는 미연결로 조회 불가 |

Windows 경고·오류 건수는 침해나 공격 탐지 결과가 아닙니다. 네트워크 어댑터 연결은 인터넷 접속 성공을 뜻하지 않습니다. 방화벽은 설정을 읽기만 합니다. 상단의 연결 없음 및 SDP 미연결이 보여도 PC 자체 조회는 별도로 사용할 수 있습니다. 읽지 못한 값은 확인 불가와 이유로 남습니다.

## 2. 준비와 폴더 열기

Windows, Windows PowerShell, Node.js 24.19.0과 함께 제공되는 npm이 필요합니다. Node.js가 없다면 공식 사이트 https://nodejs.org/ 에서 기준 버전 설치 방법을 확인하세요. 설치가 끝나면 PowerShell을 새로 열어 주세요.

받은 프로젝트의 `on-client` 폴더를 파일 탐색기에서 엽니다. **package.json, package-lock.json, student, public, src가 함께 보이는 폴더**가 맞습니다. 일부 파일만 복사하거나 기존 제출물을 지우지 마세요.

파일 탐색기 주소 표시줄에 `powershell`을 입력하고 Enter를 누르면 그 폴더에서 일반 권한 창이 열립니다. 다른 사람의 PC에서는 작성자의 바탕화면 경로를 그대로 입력하지 마세요.

다음 명령을 한 줄씩 실행합니다.

```powershell
Get-Location
Test-Path .\package.json
node --version
npm.cmd --version
```

package.json 확인 결과는 True여야 합니다. Node 기준은 v24.19.0이며 작성자 PC에서 확인한 npm은 11.17.0입니다. 다른 버전의 작동 여부를 여기서 보장하지 않습니다.

현재 package.json과 lockfile에는 외부 의존 패키지가 없습니다. 현재 앱을 실행하기 위해 별도 npm install이나 npm ci를 요구하지 않습니다. 이후 의존성이 추가되면 그 버전의 안내를 따르세요.

## 3. 실행

같은 창에서 입력합니다.

```powershell
npm.cmd run check
npm.cmd run start:pc
```

첫 명령은 기존 학생 파일의 문법 검사이며 전체 기능 시험은 아닙니다. 오류가 나면 다음 명령을 진행하지 말고 오류 전체를 기록하세요.

실행 성공 시 아래 시작 메시지가 나옵니다.

```text
라요 PC 대시보드: http://127.0.0.1:5190/
```

서버 창은 명령을 기다리는 상태로 돌아오지 않는 것이 정상입니다. 창을 닫지 말고 브라우저 주소창에 http://127.0.0.1:5190/ 을 입력하세요. 이 주소는 해당 PC 안에서만 접속하는 주소입니다. 다른 PC에서 켜면 그 PC의 값을 읽습니다. 휴대전화에서 작성자 PC의 앱을 여는 주소가 아닙니다.

## 4. 화면 확인 · 한 번에 하나씩

1. 내 PC 상태에서 CPU·메모리·디스크의 값, 단위, 측정 시각을 확인합니다. GB는 10진 단위여서 Windows 표시와 차이가 날 수 있습니다.
2. 다시 조회를 누릅니다. 새로 읽는 중 표시 뒤 시각이 갱신되는지 봅니다. 두 번 이상 성공하면 직전 비교·추이·기록을 봅니다.
3. 연결·Windows 기록을 선택하고 다시 조회를 누릅니다. 최대 25초 정도 기다립니다. 실제 값 또는 확인 불가와 이유가 나와야 합니다.
4. 자세히 보기에서 프로필별 방화벽과 System/Application 건수·조회 범위를 확인합니다. 경고·오류 숫자만으로 공격이나 침해라고 판단하지 마세요.
5. 키보드만 쓸 때는 Tab/Shift+Tab으로 이동하고 Enter/Space로 버튼과 상세를 실행합니다. 왼쪽 메뉴에서는 위·아래 방향키도 사용할 수 있습니다.

값은 고정된 예시 숫자와 일치할 필요가 없습니다. CPU는 약 1초 동안의 평균이고 각 항목의 측정 시각은 조금 다를 수 있습니다. 실패를 정상이나 0건으로 바꾸지 않습니다. 기록은 새로고침하면 초기화됩니다.

## 5. 종료와 재실행

실행한 PowerShell 창에서 Ctrl+C를 누릅니다. `일괄 작업을 끝내시겠습니까`가 나오면 Y를 입력합니다. 브라우저 탭만 닫으면 서버는 종료되지 않습니다.

다시 실행할 때는 같은 on-client 폴더에서 `npm.cmd run start:pc`를 실행하고 주소를 엽니다. 이미 켜져 있으면 서버를 또 실행하지 말고 기존 화면에서 다시 조회를 누르세요.

## 6. 막혔을 때

| 보이는 문구·현상 | 다음 행동 |
|---|---|
| node 또는 npm.cmd를 찾을 수 없음 | Node 설치 여부를 확인하고 새 PowerShell에서 버전을 다시 확인 |
| package.json을 찾을 수 없음 / ENOENT | Get-Location과 Test-Path로 on-client 폴더인지 확인 |
| Missing script: start:pc | 이 안내와 함께 배포한 최신 package.json인지 확인. 기존 파일을 임의로 덮어쓰지 말고 안내자에게 파일 버전 차이를 전달 |
| npm.ps1 실행 정책 오류 | 명령을 npm.cmd run start:pc로 입력. PC 실행 정책을 변경하지 않음 |
| EADDRINUSE / 5190 사용 중 | 기존 라요가 켜져 있는지 확인하고 그 화면 사용. 다른 프로그램을 임의로 종료하지 않음 |
| 사이트에 연결할 수 없음 | 서버 창의 시작 메시지와 주소 확인. 서버가 종료됐으면 같은 폴더에서 재실행 |
| 5189 화면에만 접속됨 | 현재 PC 대시보드는 start:pc로 실행하고 기본 주소 5190 사용 |
| 확인 불가 | 해당 항목의 이유와 다음 행동을 읽고 재조회. 권한이 없으면 관리자 실행·보안 설정 변경을 시도하지 않음 |
| 서버 연결 없음 / SDP 미연결 | 기존 연동 기능의 제한. 로컬 PC 조회 성공과 다름. 실제 연결은 수업 담당자의 공식 설정 필요 |

기존 라요가 아닌 프로그램이 5190을 사용한다면, 새 PowerShell에서 아래처럼 라요만 다른 포트로 실행할 수 있습니다. 5191도 사용 중이면 실행하지 말고 안내자에게 문의하세요. 이 창을 닫으면 임시 포트 설정도 사라집니다.

```powershell
$env:ON_PORT = '5191'
npm.cmd run start:pc
```

이 경우 시작 메시지의 주소 http://127.0.0.1:5191/ 을 사용합니다. 이 명령은 방화벽·네트워크 설정을 바꾸지 않습니다.

해결되지 않으면 다음을 안내자에게 전달하세요: 막힌 단계 번호, 실행한 명령, 오류 문구 전체, Node/npm 버전. 토큰·비밀번호·API 키·설정 파일 원문은 보내지 마세요. 캡처에 개인 정보나 IP가 포함되면 공유 전에 가리세요.

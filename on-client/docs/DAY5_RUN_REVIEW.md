# 5일차 · 실행 안내 검토

## 사용자 확인 결과 · 2026-10-26

사용자가 “나도 됐고 옆에 자리 사람도 이거 글 보고 잘 했네”라고 보고했습니다. 사용자 본인과 옆자리 사람이 실행 안내를 보고 실행에 성공했다는 사용자 진술로 기록합니다. AI가 두 사람의 실행 과정을 직접 관찰한 것은 아닙니다. 실행한 PC·환경, 종료·재실행 및 개별 기능 확인 여부는 별도로 전달되지 않았으므로 확인했다고 주장하지 않습니다. 추가로 막힌 단계나 오류 문구는 보고되지 않았습니다.

이하의 타인 실행 미확인 표시는 이 사용자 보고를 받기 전의 검토 기록입니다. 현재는 안내를 통한 타인 실행 성공 보고를 접수한 상태입니다.

## 짧은 안내로 정리

START_HERE.md는 준비·폴더 열기·실행·주소·종료 중심으로 줄였습니다. 기존 상세 안내는 RUN_TROUBLESHOOTING.md로 보존했습니다. 타인이 직접 확인할 빈 체크 항목 세 개를 넣었으며, 타인 실행 결과는 여전히 미확인입니다. 이번 정리는 문서만 수정하며 앱 코드는 바꾸지 않습니다.

## 문제와 원인 구분

사용자가 전달한 요청문에는 실제 막힌 단계·오류 문구가 없었습니다. 타인의 실행 실패나 코드 결함을 추정해 기록하지 않습니다.

직접 문서를 대조해 확인한 안내 문제: 기존 README와 STUDENT_RUNBOOK은 22단계 제공 화면 실행 및 5189를 안내하며, 이후 추가한 start:pc와 5190을 먼저 안내하지 않았습니다. 따라서 현재 대시보드 사용 안내와 실행 진입점이 달랐습니다. 기존 기록은 보존하고 README 앞부분에 현재 안내를 추가했습니다.

- docs/START_HERE.md: 작성자 PC 절대 경로에 의존하지 않는 처음 실행 안내. 준비·폴더·명령·확인·종료·재실행·문제 해결·타인 확인 양식.

## 확인 결과와 한계

- 2026-10-26 작성자 PC에서 Node v24.19.0, npm 11.17.0을 실제 조회했습니다.
- 현재 package.json의 start:pc는 student/pc-server.mjs이며 기본 포트는 5190입니다. 현재 lockfile에는 외부 의존 패키지가 없습니다.
- 실제 PC 측정, Windows 조회, 재조회·서버 중단 시 오류와 복구는 앞선 2~4일차에 확인했습니다. 그 결과를 다른 사람 PC의 성공으로 바꾸어 쓰지 않습니다.
- 안내 기준 새 실행·종료·재실행 검증 결과는 아래 추가 기록을 따릅니다.
- 타인이 안내만 보고 실행: 미확인. Windows 신규 설치, Node 설치 과정, 다른 PC 일반 권한 정책, 설치 묶음·바로가기 실행: 미확인.
- 실제 다른 사람의 오류가 접수되면 안내 문제인지 코드 문제인지 추가 진단 후 필요한 파일과 이유를 제시하고 확인을 받아 수정합니다.

## 이번 단계의 직접 실행 검증

2026-10-26 기존 on-client 폴더에서 package.json 존재(True), `npm.cmd run check` 성공을 확인했습니다. 현재 사용 중인 5190을 유지하기 위해 별도 5192에서 start:pc가 지정하는 동일 진입점 `node student/pc-server.mjs`를 실행했습니다. 두 차례 각각 화면 HTTP 200, 대시보드 스크립트 포함, CPU·메모리·디스크 actual 응답의 status=ok를 확인하고 해당 시험 프로세스만 종료했습니다. 두 번째 실행은 첫 번째 종료 이후 같은 포트에서 재실행한 것입니다.

이 검증은 작성자 PC에서 수행한 서버 실행·HTTP 조회입니다. 타인의 브라우저 조작, 수동 Ctrl+C 조작 또는 신규 PC 설치를 대신 검증한 것이 아닙니다. 기존 5190 앱과 기존 제출물은 유지했습니다.

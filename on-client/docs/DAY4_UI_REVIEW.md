# 4일차 · 다시 조회·대기·오류 안내

학생 영역의 pc-dashboard.mjs, pc-system-view.mjs, pc-dashboard.css를 수정했습니다. 기존 student/extension.mjs의 DOM 표시 계약을 확인했고 유지했습니다. 선택 사항 appearance.json은 없으며 현재 런타임의 로더도 확인되지 않아 생성하지 않았습니다. 제공 public/app.js·src/server.mjs·인증·판정 코드는 수정하지 않았습니다.

PC 상태의 핵심 기능 CPU·메모리·디스크를 맨 위 카드에 유지했습니다. 두 화면의 추가 기능 버튼을 「다시 조회」로 통일했습니다. 로딩 중 문구·시각적 표시·aria-busy, 버튼 비활성화로 중복 요청을 방지합니다. 이전 자료는 표시된 측정 시각 기준임을 안내합니다. 실패 응답은 항목·이유·다음 행동을 오류 영역에 표시하며 예제나 이전 정상값으로 대체하지 않습니다.

## 재실행

기존 on-client 폴더에서 `npm run check` 후 `npm run start:pc`를 실행하고 http://127.0.0.1:5190/ 을 엽니다. 이미 실행 중이면 브라우저 새로고침으로 학생 화면 파일 변경을 읽습니다. 서버 종료는 해당 실행 창의 Ctrl+C입니다.

## 직접 확인 순서

1. 내 PC 상태에서 실제 측정과 시각·단위를 봅니다.
2. Tab으로 다시 조회에 이동하고 Enter 또는 Space로 실행합니다. 대기 중 표시와 비활성화, 완료 뒤 버튼 포커스를 확인합니다.
3. 왼쪽 메뉴는 Tab/Enter 또는 위·아래 방향키로 이동합니다. 연결·Windows 기록에서 같은 방식으로 조회합니다.
4. 서버를 종료한 뒤 다시 조회하면 실패 항목과 이유·다음 행동이 표시되는지 확인합니다. 이전 정상값을 현재값으로 표시하지 않아야 합니다.
5. 서버 재실행 후 같은 버튼으로 회복되는지 확인합니다. 상세는 Tab으로 이동하고 Enter/Space로 펼칩니다.

## 포장 지원 범위

이 결과는 npm run start:pc 실행에서 확인할 대상입니다. package-app은 아직 구현되지 않았습니다. 학생 추가 화면·측정 모듈·CSS·기존 제공 파일과 pc-server.mjs 실행 진입점을 향후 포장에 포함해야 합니다. extension.mjs 하나만 복사하거나 제공 화면 수정만으로 설치형에 반영된다고 가정하지 않습니다. 설치형의 작동 여부는 포장 단계에서 별도 검증합니다.
